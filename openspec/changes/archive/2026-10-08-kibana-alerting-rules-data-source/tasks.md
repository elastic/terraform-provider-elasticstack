## 1. Read alerting rule execution info through the `elasticstack_kibana_alerting_rules` data source

- [x] 1.1 Register the `elasticstack_kibana_alerting_rules` data source with the provider, with inputs `space_id`, `rule_id`, `filter` and `kibana_connection`, and the Computed `id` and `rules` list. Its resource identity is the configured `rule_id`, or a constant sentinel when `rule_id` is not set, and lookup versus search is chosen by whether `rule_id` is configured, never by the resolved identity. Verify with the envelope contract test and a routing unit test showing that a search never calls the single-rule fetch with the sentinel.
- [x] 1.2 Validate input at validate time: `rule_id` and `filter` together, and an empty string for either, are errors with no API call, while setting neither is valid; do not use an exactly-one-of validator. Verify with schema validator unit tests for all four cases.
- [x] 1.3 Resolve `space_id` to its effective value (`default` when omitted), query that space, write the effective value back to `space_id` in state, and set `id` to `<space_id>/<rule_id>` for a lookup and `<space_id>` otherwise. Verify with unit tests for omitted and configured `space_id` that state, `id` and the queried space agree.
- [x] 1.4 Map each rule to a `rules` element with `id`, `name`, `rule_type_id`, `consumer`, `enabled`, `tags`, `scheduled_task_id`, `last_execution_status` and `last_execution_date`: the date is UTC RFC3339 with exactly three fractional digits and non-UTC input is normalised, an absent status, a never-executed rule or an unparseable time gives null, an absent `scheduled_task_id` is null, and no tags gives an empty set. Verify with mapper unit tests asserting exact output strings for each case.
- [x] 1.5 Look up a single rule by plain `rule_id`, returning a one-element `rules` list; a composite-looking `rule_id` is treated as a literal ID, and an unknown rule ID, an unknown space and authorization failures produce error diagnostics with no partial results. Verify with unit tests for the lookup path and acceptance tests for an existing rule, an unknown ID, and an unknown space surfacing as an error rather than an empty list.
- [x] 1.6 Return every matching rule when searching, across all result pages, with `filter` sent unmodified, results sorted by name ascending and `per_page` set explicitly to 100. The read fails as a whole if any page fails, including a later page, and error diagnostics include the API response body. A reported total above 10,000 fails with a diagnostic asking the practitioner to narrow `filter`, with no truncated list. A missing search endpoint on the connected Kibana surfaces as an API error with no version gate. Verify with unit tests against a stub Kibana covering multiple pages, the explicit page size, termination on an empty page, the over-10,000 error, failure on a later page discarding earlier results, error-body surfacing, and an endpoint-not-found response.
- [x] 1.7 Search rules in the data source when `rule_id` is not set: with `filter` it returns the rules Kibana returns for that filter, with no selector it returns every rule in the space, results are ordered by name, a successful search that matches nothing, or a space with no rules, returns `found=true` with an empty `rules` list rather than the envelope's not-found error, an invalid filter or an authorization failure produces an error diagnostic with no partial results, and the read sends no create, update, enable, disable or delete request and reflects current values on every read. Verify with a unit test that an empty search result yields `found=true`, a unit test for the authorization failure case, and acceptance tests for a filtered search, an unfiltered search, ordering by name and no matches, tolerating null execution fields for rules that have not yet run.
- [x] 1.8 Document the data source with a docs template, an example and the generated docs page: the inputs, the `rules` attributes and their null behaviour, a single-rule lookup example reading `last_execution_status`, guidance to set `filter` in large spaces, and a statement that it replaces the removed resource attributes. Verify the generated docs page contains each of those elements.
