## Why

`elasticstack_fleet_agent_download_source` never maps the Kibana Fleet API's `secrets` request fields (`secrets.ssl.key`, `secrets.auth.password`, `secrets.auth.api_key`) on either `POST /api/fleet/agent_download_sources` or `PUT /api/fleet/agent_download_sources/{sourceId}`. Today `ssl.key`, `auth.password`, and `auth.api_key` can only be sent as plaintext literals; there is no way for a practitioner to store this material as a managed Fleet secret instead.

This closes the gap flagged in [`#5242`](https://github.com/elastic/terraform-provider-elasticstack/issues/5242): the Kibana API gap scanner found `secrets.ssl.key` and `secrets.auth.*` present on both request bodies' schema but absent from the Terraform schema and model. The issue author rescoped the ask in review to: (1) wire `ssl.key` through `secrets.ssl.key`, and (2) add write-only sibling attributes (`ssl.key_wo`, `auth.password_wo`, `auth.api_key_wo`) rather than deprecating the existing plain attributes.

A follow-up human decision (recorded verbatim in design.md) supersedes the automated implementation research's proposed `_wo`/`_wo_version` companion-attribute mechanism in favor of the repo's mandatory `internal/utils/writeonlyhash` hash-in-private-state standard ([`coding-standards.md:61-63`](../../../dev-docs/high-level/coding-standards.md), [`writeonly-secret-hashing.md`](../../../dev-docs/high-level/writeonly-secret-hashing.md)). That decision also corrects two behaviors the research got wrong by probing a live Kibana 9.5.5 stack: omitting `secrets.*` while still sending `ssl`/`auth` clears the existing secret (it is not a safe no-op), and the `writeonlyhash` helper's bcrypt backend errors outright (does not silently truncate) on secrets longer than 72 bytes such as PEM-formatted keys, so it must be fixed before this resource can adopt it for `ssl.key_wo`.

## What Changes

- Add `ssl.key` → `secrets.ssl.key` wiring: when connected to a Fleet Server that has adopted secret storage for SSL (gated at Fleet-Server-version-runtime, not stack version — unaffected by this change's Terraform-side version floors), send `ssl.key` under `secrets.ssl.key` instead of plain `ssl.key`. Keep the existing `ssl` 9.1.0 and `auth` 9.4.0 Terraform-side minimum-version gates unchanged; add no new gate for `secrets.ssl.key`.
- Add three write-only sibling attributes: `ssl.key_wo`, `auth.password_wo`, `auth.api_key_wo`. No `_wo_version` companion attributes. Drift on each is detected via `internal/utils/writeonlyhash` in a new `ModifyPlan` implementation, per the mandatory standard in `coding-standards.md:61-63`. This supersedes the `_wo_version` design from the automated implementation-research comment.
- Fix the 72-byte bcrypt input limit in `internal/utils/writeonlyhash/hasher.go`'s `passwordBytes`: when the salted value exceeds 72 bytes, pre-hash with SHA-256 and base64-encode before bcrypt; values at or under 72 bytes hash exactly as before (existing stored hashes, e.g. for `elasticsearch_connector`, remain valid). Add a unit test covering a PEM-sized value.
- Add secret-write semantics for all three secret-bearing fields, driven by a GET immediately before each PUT: when the write-only value's hash is unchanged since the last apply, send `{id: <existing-secret-id>}` to reference the already-stored secret instead of resending the literal; send the literal (first apply, or hash changed) otherwise. If the pre-PUT GET returns no secret id for a field (Fleet Server secret storage unavailable, so Kibana stored the value as merged plaintext), resend the literal from configuration rather than attempting an `{id}` reference. Resending the same literal mints a new secret id each time; Kibana does not validate caller-supplied ids in the `{id}` arm.
- Add one object-level validator on `auth` consolidating credential-mode rules across both the plain and write-only forms: a configured `username` requires `password` or `password_wo`; `password`/`password_wo` are mutually exclusive; `api_key`/`api_key_wo` are mutually exclusive; any member of the password family (`password`/`password_wo`) conflicts with any member of the api_key family (`api_key`/`api_key_wo`).
- Resolve the architectural gap that currently makes private state unreachable from this resource's Create/Update path (see design.md Decision 6): extend `entitycore.KibanaWriteRequest[T]` with a `Private PrivateStateStorage` field threaded through from the envelope, and add a bespoke `Delete` override on `*agentdownloadsource.Resource` to clear stored hashes, mirroring the `elasticsearch_connector` precedent.
- Document the Terraform CLI 1.11 minimum required for write-only arguments, reusing the existing note pattern from other `_wo` resources in this provider.
- Update the OpenSpec requirement "Auth and secrets not in v1 schema" (and the "Optional ssl attribute" / auth requirements it interacts with) to reflect that `secrets.ssl.key`, `secrets.auth.password`, and `secrets.auth.api_key` are now reachable through the write-only attributes, while the `{id}`-reference mechanism itself remains an internal implementation detail (not a user-facing schema shape).

## Capabilities

### Modified Capabilities

- `fleet-agent-download-source`: Adds `ssl.key_wo`, `auth.password_wo`, `auth.api_key_wo` write-only attributes backed by `secrets.ssl.key`/`secrets.auth.*`; adds `writeonlyhash`-based drift detection via a new `ModifyPlan`; adds GET-before-PUT id-vs-literal secret write logic; consolidates auth credential-mode validation into one object-level validator; wires plain `ssl.key` through `secrets.ssl.key` when Fleet Server secret storage is available.

## Impact

- **Changed code**: `internal/fleet/agentdownloadsource/schema.go` (new `_wo` attributes, object-level auth validator), `internal/fleet/agentdownloadsource/models.go` / `models_ssl.go` (secret-reference request types, hash-aware write-vs-reference branching), `internal/fleet/agentdownloadsource/read.go` (GET-before-PUT secret id lookup), `internal/fleet/agentdownloadsource/write.go` (wire `Private` through Create/Update), `internal/fleet/agentdownloadsource/resource.go` (new `ModifyPlan` and `Delete` methods, new `resource.ResourceWithModifyPlan` assertion), `internal/fleet/agentdownloadsource/modify_plan.go` (new file), `internal/fleet/agentdownloadsource/secret_hash.go` (new file), `internal/entitycore/kibana_resource_envelope.go` (`KibanaWriteRequest[T].Private` field), `internal/utils/writeonlyhash/hasher.go` (bcrypt 72-byte fix).
- **New/updated acceptance tests**: `internal/fleet/agentdownloadsource/acc_test.go` and `testdata/TestAccResourceFleetAgentDownloadSource*/` — write-only create/rotate/no-op-on-unchanged-config for all three fields, mixed plain+write-only rejection via the consolidated validator, secret-storage-unavailable literal-resend fallback, PEM-sized `ssl.key_wo` value (exercises the bcrypt fix), delete clears stored hashes.
- **New unit test**: `internal/utils/writeonlyhash/hasher_test.go` — PEM-sized (>72 byte) value hashes and verifies successfully pre- and post-fix behavior parity for ≤72-byte values.
- **Docs**: `docs/resources/fleet_agent_download_source.md` and `examples/resources/elasticstack_fleet_agent_download_source/` will need `_wo` examples and the Terraform CLI 1.11 minimum note once implemented (not produced in this proposal-only change).
- **No `generated/kbapi` changes**: the generated client already exposes `Secrets.Ssl.Key` and `Secrets.Auth.{ApiKey,Password}` (each a two-arm `anyOf`: `{id: string}` object or raw string) on both request bodies; no regeneration is required.
- **Backward compatibility**: additive only. Existing configurations using plain `ssl.key`/`auth.password`/`auth.api_key` are unaffected and continue to send plaintext literals unless the practitioner opts into the new `_wo` attributes. No attribute is removed or renamed.
